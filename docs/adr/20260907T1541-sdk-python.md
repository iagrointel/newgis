# ADR 20260907T1541 — SDK Python gerado do OpenAPI (item L7-08-b-sdk-python)

## Contexto

O item pede um SDK Python `plat` para consumir a API sem que o usuário escreva HTTP à mão, com
paridade declarada contra o `ArcGIS API for Python`. A regra do item é literal: o SDK tem de ser
**gerado** do `docs/openapi.json` (nunca escrito rota a rota à mão), com uma camada ergonômica por
cima, escrita à mão, cobrindo o que a API realmente tem hoje.

## Decisão

1. **Duas camadas, dois pacotes, um `pip install`.** `sdk/python/src/plat_gerado/` é gerado por
   `openapi-python-client` (`--meta none`, sem metadado próprio) a partir de
   `docs/openapi.json`; `sdk/python/src/plat/` é escrita à mão e importa `plat_gerado` como
   dependência. Um único `sdk/python/pyproject.toml` (setuptools, `src` layout) empacota os dois,
   satisfazendo `pip install ./sdk/python` sem exigir dois comandos.
2. **Config de geração comitada** (`sdk/python/config_geracao.yaml`) é a única fonte de verdade
   sobre nomes de pacote/classe. `scripts/gerar_sdk.sh` (raiz do repo) é o único jeito de gerar —
   nunca uma chamada solta ao `openapi-python-client` num terminal, para que qualquer regeração
   (por qualquer pessoa, em qualquer trilha) produza byte a byte o mesmo resultado.
3. **Duas colisões de nome corrigidas na FONTE, não no gerador.** O OpenAPI tinha três pares de
   classes Pydantic com o MESMO nome Python em módulos diferentes (`Pagina`, `LoteEntrada`,
   `LoteSaida`, um em `app/auth/modelos.py` e outro em `app/catalogo/modelos.py`). O FastAPI já
   desambigua a CHAVE do componente (`app__auth__modelos__Pagina` vs `app__catalogo__modelos__Pagina`),
   mas o campo `title` do schema (que o gerador usa para nomear a classe, com
   `use_path_prefixes_for_title_model_names` no padrão) continuava `"Pagina"` para os dois —
   colisão real, não do gerador. Corrigido com um `model_config = ConfigDict(title="...")` explícito
   nas 6 classes (título único, sem tocar no nome Python nem em nenhum código que já as importa por
   nome — `grep` confirmou que nenhum teste depende do `title` literal). `class_overrides` do
   `openapi-python-client` NÃO resolveria isso: ele indexa pelo `ClassName` já resolvido do
   `title`, que era o MESMO para os dois lados — não dava para apontar dois destinos com uma chave
   igual.
4. **A camada ergonômica devolve dicionário, não objeto `attrs`.** `Plataforma.itens.criar(...)`
   etc. devolvem o corpo JSON decodificado (o mesmo `dict` que a API manda), não os objetos
   `attrs` do gerado. Quem precisa do objeto tipado usa `plat_gerado` direto (instalado junto,
   `from plat_gerado.api... import ...`) — ver `sdk/python/exemplos/05_pastas_e_mover.py`, que
   mistura as duas camadas de propósito, provando que a ergonômica não trava quem precisa de mais.
5. **`.camadas`/`.mapas` são VISÕES de `.itens`, não rotas.** Não existe `/api/camadas` nem
   `/api/mapas` na API hoje — "camada"/"mapa" são valores do campo `tipo` de um item do catálogo.
   Implementar `.tiles`/`.exportar()` da hipótese original do item exigiria rotas que também não
   existem (dependem de `L2-04-servicos-esri-ogc`, PARCIAL, e de itens de raster/exportação do L1/L5
   ainda não mesclados) — ficaram FORA desta trilha, documentados em `sdk/python/README.md`, em vez
   de apontar para uma rota que sempre devolveria 404.
6. **Tokens de serviço exigem SESSÃO, não outro token — em TODA rota de `/api/tokens`** (não só
   criar/renovar). `Plataforma.entrar()` guarda o `Client` de sessão do login (o mesmo objeto,
   `get_httpx_client()` cacheado preserva o cookie) e `Tokens` o reusa; sem sessão viva (um
   `Plataforma(url, token=...)` direto), `.tokens.*` bate no mesmo `403 so_sessao` que a API
   devolveria a qualquer token — é o modelo de autorização real, não um limite do SDK.
7. **Erros como Problem Details (RFC 9457) SEM mudar o contrato de fio da API.** O contrato real
   (`{"erro","mensagem","detalhe","req_id"}`, ADR 0002 §14, decisão D18 — já fechada, este item não
   a reabre) é traduzido em `ErroPlataforma` com atributos no vocabulário da RFC 9457 (`status`,
   `tipo`~type, `titulo`~title, `detalhe`~detail, `instancia`~instance = `req_id`, que casa com
   `plat.log_acesso`). `erro_de_corpo()` sempre decodifica o `content` bruto da resposta, nunca o
   `.parsed` do gerado — o gerado só tipa os status DOCUMENTADOS no OpenAPI (normalmente só 2xx e
   422); a maioria dos erros reais (401/403/404/409) fica sem modelo e `.parsed` viria `None`.
8. **Cobertura "100% das rotas" testada pelo nome real do módulo gerado, não por suposição.** O
   `operationId` do FastAPI usa `__` (duplo) onde o caminho tem `{id}`
   (ex. `ver_api_tokens__id__get`); o `openapi-python-client` nomeia o módulo com
   `PythonIdentifier(operationId, ...)`, que colapsa para `_` simples
   (`ver_api_tokens_id_get.py`). O teste de cobertura importa essa MESMA função do gerador
   (`openapi_python_client.strings.PythonIdentifier`) em vez de reimplementar a normalização — a
   primeira versão do teste reimplementou errado e "achou" 100+ rotas fantasma.
9. **Teste de reprodutibilidade gera numa pasta IRMÃ do repositório, não em `/tmp`.** O post-hook
   `ruff format .`/`ruff check .` do próprio `openapi-python-client` busca `pyproject.toml`
   subindo diretórios a partir do destino; gerar fora da árvore do repo faz o `ruff` cair nos
   padrões embutidos dele (outro `target-version`, gera `Self` de `typing` em vez de
   `type[T]`/`TypeVar`) e o "diff" vira ruído do ambiente de teste, não do gerador.

## Consequências

- Toda rota nova do produto ganha SDK automaticamente ao rodar `scripts/gerar_sdk.sh` de novo — a
  camada ergonômica só precisa de código novo quando alguém quiser um método mais confortável que
  a chamada gerada crua (que já funciona, como o exemplo 05 mostra).
- A correção de título das 6 classes muda `docs/openapi.json` (2 linhas de `title`, nenhuma
  mudança de schema/tipo/obrigatoriedade) — reproduzível por `make openapi` (fora de trilha) ou
  pela chamada direta documentada no brief (dentro de trilha).
- `.tiles`/`.exportar()`/rotas de FeatureServer de verdade ficam como trabalho futuro nomeado, não
  como método que sempre devolveria 404.

## Fontes

DEV-python (conhecimento geral do papel esri, sem acesso à internet nesta trilha), OPENAPI-PY
(código-fonte lido de `openapi_python_client` instalado, versão 0.29.1), OAS31 (OpenAPI 3.1,
`docs/openapi.json` comitado), RFC9457 (vocabulário Problem Details, aplicado por analogia — a API
não fala esse formato de fio, ver decisão 7 acima).
